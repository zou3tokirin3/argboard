## 目的

新しい発見を1行で入れるとき、すでにプロジェクトにあるタグ（例: 人物・書類）を
**入力のついでに**付けられるようにする。サイド（インスペクタ）へ戻って付ける往復を減らし、
整理用タグを「あとから」だけでなく「いま知っているラベル」でも乗せられるようにする。

出典: 2026-09-10 人間フィードバック（発見入力時に既存ラベルをついでに付けたい）

関連: T031（サイド付与・サジェスト・上限12・明示新規作成） / T026（行内記法） /
T027（出典サジェスト・hold） / T020案B制約1（主要導線はタグなしで完結）

## 背景（起票時メモ）

- T031は意図的に **キャプチャ行内 `#tag` をやらなかった**（「最初から付ける」導線になり案B制約1を崩すため。痛み観測時のみ別カード）。本カードがその痛みの起票
- いまタグ付与はサイドのみ。連続キャプチャ中に「これは人物」「これは書類」と分かっていても、Enter → 選択 → サイド、の往復が要る
- 候補は **現プロジェクトの既出 `cards[].tags` のみ**（T031/T027と同じ流儀。タグマスタ・Entity辞書は作らない）
- ユーザー表現は「既存のラベルがあるなら」＝ **新規タグ作成はキャプチャから必須にしない**。作成はサイドの明示新規作成のままが第一候補（readyで確定）

### 採択方針（2026-09-10 人間）

**本カードの本体はクリック／タップで付けるチップ帯。** いまサイドでプチプチクリックしている操作を、キャプチャ付近に寄せる。

- **採択: キャプチャ直下（または入力近く）に既出タグのチップ帯** — クリックで「この発見に付ける」をトグル。Enter でタイトル保存時に選んだタグも一緒に載せる
- **行内 `#tag` 入力は任意の後追い**（サポートしてもよいが本カードの必須ではない）。コストが跳ねるなら別カード
- タグなしでも今まで通り 1 行+Enter（案B制約1）
- 新規タグ作成はキャプチャからはやらない（サイドの明示新規作成のまま）

落ちた案: Enter後の確認ステップ（リズムを崩す）／最初から `#` サジェスト必須化

## 受け入れ条件（起票時ドラフト・ready時に確定）

- [ ] 発見キャプチャ近くに既出タグのチップが出る（タグが0件なら帯は出ない／邪魔しない）
- [ ] チップをクリックすると、これから入れる発見にそのタグが付く（複数可・再クリックで外せる想定）
- [ ] Enter で保存したカードに、選んだタグが入っている
- [ ] タグを選ばない従来の1行+Enterは今まで通り動く（案B制約1）
- [ ] 候補は現プロジェクトの既出タグのみ（マスタ新設なし・キャプチャから新規作成しない）
- [ ] 種類上限12・未定着の抑止方針と矛盾しない（T031）
- [ ] 考察キャプチャへ同じチップを載せるか／載せないかが決まっている
- [ ] flow しきい値（本体行 +200 / 操作 +3 / 概念 +2 / gzip +8KB / Won't）を意識し、超過見込みなら評価パケットへの人間GOが作業ログにある
- [ ] 最新コミットで check / test / smoke が緑
- [ ] 人間が「キャプチャ近くのクリックで既存ラベルを付けられる」と確認する

## 確認観点（gate: human のとき）

表示: タブ・左上が **`ARGBoard · <release>+<id>`**（review 中）または **`ARGBoard · <release>`**（done 後）であること。
`<release>` は `ui/release.ts` の `APP_RELEASE`。review 中は `APP_PREVIEW` に本カード id を入れる。

- [ ] 既出タグ（人物・書類など）がある状態で、キャプチャ近くのチップをクリックしてから発見を入れ、タグが付いている
- [ ] チップを触らず Enter しても従来どおり保存できる
- [ ] 付けたタグが発見ログ／サイドで見え、検索でも拾える

## このカードでやらない

- タグマスタ・固定初期タグ・意味カテゴリ色（§1・T031）
- 行内 `#tag` サジェストの必須化（任意後追い・別カード可）
- 出典 `@` サジェスト（T027・hold中）
- 一括タグ付け・リネーム／統合の拡張（T032済み範囲外の新導線）
- タグ起点フォーカスの変更（T033）
