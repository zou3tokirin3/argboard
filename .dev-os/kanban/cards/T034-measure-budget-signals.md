## 目的

現行の実装ゲート（PLAN §4「実装ゲート」/ §11-3）は**行数という単一の stock 指標**で発火するが、
その数字が一意に出せていない。T031–T033 パケット §0 が「過去パケットの実数が互いに再現できない」と
自己申告しており、実際いま「本体行数」には 4,385（`ui/` 全部 + `serve.ts`）と 3,233（TS/TSX のみ）の
2つの値がある。**ゲートが数字の判定ではなく数え方の交渉になっている。**

本カードは判断基準を変えない。**測るものを一意にし、1コマンドで出せるようにするだけ**。
T035（基準そのものの改訂）を実データで議論できる状態にするのが役割。

## 背景（現物確認・2026-07-25 実測）

| 指標 | 実測 | 出し方（検証済み） |
|---|---:|---|
| 本体行数（`ui/` 全部 + `serve.ts`） | 4,385 | `wc -l serve.ts ui/*` |
| 本体行数（TS/TSX のみ） | 3,233 | 同上から `.css` `.html` を除外 |
| 本体ファイル数 | 13 | 同上 |
| テスト行数 | 1,273 | `wc -l tests/smoke.ts tests/unit/*` |
| スモーク本数 | 5 | `tests/smoke.ts` の ①〜⑤ コメント |
| 配布サイズ（gzip） | 27,972 B | `gzip -c dist/bundle.js \| wc -c` |
| 操作の数（ユニーク testid） | 41 | `grep -oh 'data-testid="[^"]*"' ui/*.tsx \| sort -u \| wc -l` |
| 概念の数 | 77 | `types.ts` フィールド 51 + イベント種別 8 + signals 18 |

過去パケットの実数（T024=2,986/11ファイル、T026=3,126/10ファイル、T025=3,632/13ファイル）は
ファイル数の数え方だけでも 10（TS/TSX のみ）と 13（`ui/` 全部 + `serve.ts`）が混在している。

**行数がフォーマッタの関数になっている証拠**: `board.tsx` 1,106行 = 21.9KB に対し
`styles.css` 1,117行 = 18.3KB。同じ行数で中身が2割違う。deno fmt は JSX 属性を1行ずつ折るため
SVG の `<path>` 1本が12行になる。PLAN §4-5 が「一行化での帳尻合わせ禁止」を明文化していること自体が、
この指標がフォーマット依存であることを規約側で認めている。

## やること

- `deno task budget` を足し、上表の指標を**一意な定義で**まとめて出す
- 各指標について **stock（現在値）と flow（指定 ref からの増分）の両方**を出す。
  flow の既定基準は `main`（例: `deno task budget --since main`）
- 出力は評価パケット §1 にそのまま貼れる Markdown 表とする
- 定義を PLAN §4 の予算節へ1箇所だけ書き、スクリプトはそこを唯一の正本として実装する

## このカードでやらない

- **基準値・発火条件の変更**（T035）。本カードは測るだけで、何も止めない・何も通さない
- **コードのリファクタ**（T036）
- `tests/smoke.ts` を `scenarios[]` 配列へ組み替えて本数を機械カウントすること —
  smoke の構造変更は flaky リスク（§10-2）を背負うため別扱い。本カードでは既存の ①〜⑤
  コメント規約を grep して数える
- 計測の CI 化・自動実行・履歴の永続化（§12「テストCI・カバレッジ計測」の趣旨に触れる）
- 指標の良し悪しの自動判定。スクリプトは数字を出すだけで、GO/NOGO を言わない
