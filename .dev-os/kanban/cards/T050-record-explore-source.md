## 目的

探索は「1本の資料を開いて、そこから出たものを連続で放り込む」という掘り方になる。
どこを見ていて見つけたかは**キャプチャの瞬間にしか分からない**。あとから考察モードで
思い出して張り直すのは高コストで、実際には忘れる。

発見の構造（記録・不変）と意味づけの構造（判断・可変＝糸）を**別の仕組み**にして、
発見元は `Card.foundVia` に自動で残す。糸は意味づけ専用のまま維持する。

出典: 2026-08-01 人間との設計相談（探索は元資料から枝になっていく／発見と意味づけは
同じ仕組みでなくてよい）

## 背景（起票時メモ）

- 発見の構造と意味づけの構造は性質が違う。記録は不変・木・自動、判断は可変・網・意図的。
  同じ入れ物（Link）に入れると、糸を消したときに掘った経路まで壊れる
- このアプリはすでに区別を持っている（`foundAt` は「自動付与・以後不変」、`events` は
  append-only、§1「発見ログと解釈の分離」）。分けるほうが既存思想に沿う
- `foundAt`（いつ）と `foundVia`（どこから）が対になる。どちらも発見の事実で以後不変
- 発見元は糸ではないので**ボードに描かれない**。ボードは意味づけ専用のまま保たれる
- **Won't 抵触あり**（§12「カードの親子階層」）→ 評価パケット `packets/T050.md` に
  論点を出す。人間GOなしに実装しない
- 誤りの訂正は**案1（外すだけ・付け替え不可）**で確定（2026-08-01 人間判断）。
  掘り中の外し忘れは必ず起きるため、外せることは必須。付け替えUIは作らない
- T051（発見ログのツリー表示・畳み）はこのカードの `foundVia` を親に使う。順序は T050 → T051

## 受け入れ条件（起票時ドラフト・ready時に確定）

- [x] エクスポート→インポートで `foundVia` が復元する。`foundVia` を持たない既存JSONも壊れない
- [x] キャプチャのEnter連打のリズムが変わらない（打鍵が増えない）
- [x] flow しきい値（本体行 +200 / 操作 +3 / 概念 +2 / gzip +8KB / Won't）の見込みを作業ログに書く

## このカードでやらない

- 発見ログのツリー表示・畳み（**T051**）
- 発見元の付け替えUI・履歴・undo（案1の範囲外）
- `foundVia` をボード上に糸として描くこと（発見と意味づけを混ぜない）
- 複数の発見元・多重親（1カード1つだけ）
- 外部出典（`Card.url`）のサジェスト（**T027**・別物）
- まとめて発見元を外す一括操作（痛みが出たら別カード）
