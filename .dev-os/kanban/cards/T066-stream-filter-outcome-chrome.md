## 目的

仮説成否（未検証/採用/棄却）と「未検証」フィルタを追加したが、発見ログ上部の UI が横長テキストボタンの並びになり、種類の区別が付きにくい。

- **フィルタ5種**（未配置/配置済/発見/考察/未検証）が同じ `.stream__filter-btn` 見た目で並ぶ
- **タグ視点ボタン**もフィルタと同系統の pill で、検索・フィルタ・タグの境界が曖昧
- **成否チップ**（インスペクタ・選択中インライン・カードバッジ）が「未検証」「採用」「棄却」の横長 pill 3つ

発見/考察の種別トグル（`card-role-toggle`）はアイコン2択の segmented control でコンパクト。フィルタ・成否も同程度の密度とアイコン性を目指す。

出典: 2026-09-02 人間フィードバック（見た目・検索タグ・成否の視認性）

対象の目安: `ui/stream.tsx`（フィルタ・`TagFocusControls`） /
`ui/thought-outcome-field.tsx` / `ui/styles.css`（`.stream__filter-btn` `.stream__tag-focus-btn` `.inspector__outcome-chip` `.stream-card__outcome`）

## 受け入れ条件

- [ ] 発見ログのフィルタが **配置系 / 種別系 / 成否系** で一目で区別できる（色・グループ分け・アイコン等。実装は impl 裁量）
- [ ] タグ視点ボタンがフィルタ行と混ざらない（ラベル・レイアウト・スタイルのいずれかで分離）
- [ ] 成否 UI（インスペクタ・選択中 meta-tools・非選択バッジ）が横長テキスト3ボタンよりコンパクトで、アイコンまたは短い記号で状態が読める
- [ ] 各操作の `aria-label` / `title` / `aria-pressed` は維持され、キーボード操作の意味は変えない
- [ ] フィルタ・タグ視点・成否の **ON/OFF ロジックと AND 条件** は現状どおり
- [ ] flow しきい値（本体行 +200 / 操作 +3 / 概念 +2 / gzip +8KB / Won't）を意識し、超過見込みなら評価パケットへの人間GOが作業ログにある
