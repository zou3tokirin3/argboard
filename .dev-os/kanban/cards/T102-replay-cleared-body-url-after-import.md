## 目的

旧ビルドで空にした body/url が、JSON 書き出し→読み込み後の履歴再生（`viewThrough`）で古いメモ・URL のまま残って見えるずれを直す。

## 背景・問題

T097（PR #2）で `card_updated` のリプレイ（`ui/project.ts`）を部分更新に変えた。
`title` / `body` / `url` は **イベントにキーがあるときだけ** 適用し、キーがなければ「変更なし」として扱う。

旧ビルド（T097 より前）は `card_updated` に3項目すべてを載せており、body/url を空にしたときは空値として記録していた。
ところが JSON 書き出しでは空値が落ちるため、読み込み後のイベントでは `body` / `url` のキーそのものがなくなる。
その結果、リプレイはそのイベントを「body/url は変更なし」と解釈し、`viewThrough`（履歴再生）では空にする前のメモ・URL が残って見える。

- 影響は **履歴再生ビューだけ**。現在のカードデータ（`project.cards`）は影響を受けない
- 書き出し→読み込みを経ていないローカルのログ（空値のキーが残っているもの）では起きない
- 確認方法: node からリプレイのコード（`viewThrough`）を直接呼んで再現した。ブラウザ上ではまだ確認していない

出典: 2026-10-27 PR #2（T097）のレビューで判明。人間の指示で別カードに切り出し。

## 直し方（未定・候補）

どれにするかは ready にするときに決める。

- A. 書き出し時に `card_updated` の空文字列を落とさず残す（新しく書き出したファイルだけ直る）
- B. 読み込み時に旧形式（3項目フル形）の `card_updated` を見分け、欠けた body/url を「空にした」に正規化する
- C. イベントやプロジェクトに版マーカーを持たせ、旧形式と部分更新形式をリプレイ側で区別する
