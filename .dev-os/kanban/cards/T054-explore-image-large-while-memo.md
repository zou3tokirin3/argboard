## 目的

探索で貼ったスクショの**中身（文字）を読みながら**、同じ画面でメモを書きたい。
「画像を開きながら見ながらメモ」＝拡大表示とテキスト入力が同時に成立すること。

T045 で初回貼付のステージングは大きめプレビューになったが、**カード確定後の追記**
（発見ログサムネクリック → `ExploreCompose`）では画像が 96px サムネに縮み、
文字が読めない。ここが主なギャップ。

出典: 2026-08-05 人間要望（貼り付け画像を大きく確認しながらメモしたい）

## 背景（起票時メモ）

- **初回貼付**（`ExploreImageStaging`）: プレビュー `max-height: min(52vh, 520px)` — ある程度大きい
- **追記**（`ExploreCompose`）: `card-image-field--inline` で幅 96px — **小さすぎて文字が読めない**
- フルスクリーン／ライトボックス／ピンチズームは未実装
- T045 受け入れ「大きめ表示で足りる」は staging 時点。compose 再開時の体験は未カバー
- 候補:
  - **A**: `ExploreCompose` も staging と同レイアウト（上に大プレビュー + 下に fields）
  - **B**: 画像クリックでオーバーレイ拡大、メモ欄は横または下に固定
  - **C**: 探索画面を一時的に「画像左・メモ右」2ペインにする（狭い viewport は縦積み）
- 罠: 探索の縦スクロール（キャプチャ + 大画像 + 発見ログ）が長くなりすぎないか
- 罠: 考察モード Inspector の画像プレビューとの一貫性

## 受け入れ条件（起票時ドラフト・ready時に確定）

- [ ] 探索モードで、**確定済み画像カード**を追記するときも、文字が読める大きさで画像が見える
- [ ] その状態で title/body/url を編集できる（既存 `updateCard` / blur 保存）
- [ ] 初回貼付（staging）と追記（compose）で体験が大きく矛盾しない
- [ ] 狭い viewport でも破綻しない（縦積み等でよい）
- [ ] キャプチャ Enter の新規追加リズムを壊さない（追記モードは明示的に入る）
- [ ] T041 の1枚制限・圧縮・zip 契約を壊さない
- [ ] flow しきい値の見込みを作業ログに書く。超過見込みならパケットへの人間GOがある
- [ ] check / test / smoke が緑
- [ ] 人間が「スクショの文字を見ながら探索のままメモできる」と確認する

## このカードでやらない

- 1カード複数画像
- AI OCR / 自動文字起こし
- ボード上での画像ライトボックス
- ピンチズーム・パンの本格実装（必要なら別カード。まずは読めるサイズ表示）
- 考察モード Inspector の全面改修
