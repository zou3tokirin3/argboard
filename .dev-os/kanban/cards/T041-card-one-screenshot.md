## 目的

操作メモとして、カードにスクリーンショットを1枚貼れるようにする。
テキストだけでは残しづらい画面状態を、ローカル完結のままカードに紐づけて残す。

出典: 人間との設計会話（2026-07-27）。PLAN §12「ローカル画像ファイルの取り込み保存」は現状 Won't →
本カード着手前に評価パケットで Won't 解除の人間GOが必要。

## 決めたこと（提案採択済み・実装前の契約）

- **1カードあたり画像は最大1枚**（差し替え可・複数枚はしない）
- 実行時保存: Project JSON には参照のみ。実体は IndexedDB の Blob ストア（OPFS は後回し）
- 持ち出し: **`project.json` + `media/` の zip** を本線のエクスポート／バックアップとする
- 読み込み: 既存の `.json` 単体も継続受理。画像ありプロジェクトは `.zip` で完全復元
- 取り込みUX: ペースト（clipboard の `image/*`）を第一級。ファイル選択は副次でよい
- 取り込み時: 長辺制限＋ WebP/JPEG 圧縮（スクショ用途の軽量化）

`Card.image` は現行の「外部URL文字列」から **ローカル添付参照**へ意味を移す（外部URL専用は本カードではやらない／残すなら別フィールド検討はスコープ外）。

## やること

- カード編集UIでスクショ1枚の貼付・差し替え・削除
- Blob の保存／読込／カード削除時の GC（参照が消えた実体を捨てる）
- エクスポートを zip（`project.json` + `media/<id>.webp` 等）に拡張
- インポートで zip 往復の完全復元（既存 `.json` は従来どおり）
- PLAN §5/§6/§12 を上記契約に同期（done 前）

## このカードでやらない

- 1カード複数枚・ギャラリー・リッチなインライン画像エディタ
- OPFS / SQLite-wasm
- 外部画像URLの取得・ホットリンク専用UI
- base64 を Project JSON に直書きする単一ファイル方式
- クラウド同期・共同編集
