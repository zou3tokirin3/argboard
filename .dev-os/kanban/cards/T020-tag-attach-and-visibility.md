## 目的

自由入力タグ付けをMVPに実装する前に、**それが本当に必要かを検証する**。
ピン／未読／調査項目／糸／考察／出来事など、目的を直接表す操作で代替できないかを先に確かめる。
このカードは**探索であり、タグ付けUIを実装しない**（改訂13）。

出典: T015 / O8（旧「タグ付けと可視化切替」）。改訂13で切り直し。
関連: O5/T018（タグ非依存の動的ビュー）・T028/T029（糸・考察の最小仕様・done）・
T030（デモから意味分類タグ除去・done）・§1（意味分類はタグにしない）。

## 背景（改稿メモ＋現物）

- 旧設計: `tags` を付け／外し、タグで可視化を切り替える。唯一のタグ実データ（デモ）は
  すべて意味分類で、§1と矛盾していた → **T030でデモから除去済み**。
- 現状のタグ関連コード: スキーマ `tags?: string[]`、発見ログの表示、検索対象。
  **付ける／絞るUIは未実装**。デモも空。
- 自由入力タグは一度定着すると役割を狭めにくい（意味分類・ワークフロー状態・絞り込みの逃げ道になる）。

## 意図 → タグ以外で足りるか

| ユーザーの意図 | タグ以外の手段 | 判定 |
|---|---|---|
| 後で戻りたい | ボードに置く／考察カードを焦点に選ぶ（T018レンズ） | **足りる** |
| まだ見ていない | 発見ログの新しい順・検索。専用「未読」は未実装だが、自由タグで代用するとワークフロー状態化して資料§17に反する | **タグでは満たさない**（専用操作の観測待ち） |
| 追加で調べたい | `body` メモ／考察カード／要検討の糸 | **足りる** |
| 関係がありそう | 糸（T028） | **足りる** |
| 主張を整理したい | 考察カード（T029） | **足りる** |
| 人物・場所で見たい | 関係ベースの焦点ビュー（T018）。タグ絞り込みは改訂13で廃した | **タグでは満たさない**（T018へ） |
| 矛盾・仮説を表したい | 要検討の糸／`role:"thought"`（T030で実証） | **足りる** |

→ O8が欲しかった「付けて切り替える」は、**意味は糸・考察、視点切替はT018**に分解済み。
残るのは「未読・ピン」系の運用フラグだけだが、それは自由入力タグではなく**専用操作**で足すべき（命名・統合・誤用のコストがタグより小さい）。

## 決めたこと

### 案A（既定・採択）: MVPから自由入力タグを外す

- **タグ付けUI・タグ絞り込みは実装しない**。
- `Card.tags` は schema v1互換のため**フィールドは残す**（T030方針継続）。新規作成経路では付けない。検索対象に残っていても実害は小さい。
- PLAN §1の「タグは運用属性に限定」は、「自由タグで運用属性をやる」許可ではなく、
  **意味分類に使うな**という下限だった、と読む。運用属性が必要になったらピン／未読等の専用操作を別カードで検討する（自由タグを先に復活させない）。
- 色分け: 意味カテゴリ色はやらない。導入するなら専用操作側の表示属性とし、`Card.color` は足さない（2026-07-20方針維持）。

### 案B（不採択・制約だけ記録）: 将来自由入力タグを復活させるなら

資料§17相当のガードを必ず置く:

1. 主要導線（キャプチャ・配置・糸・考察・焦点ビュー）は**タグなしで完結**すること
2. 人物・場所・日時・仮説・矛盾の**正本にしない**（正本はカード／糸／role）
3. 未読・保留などの**ワークフロー状態にしない**
4. 削除・リネーム・統合ができること（定着後に意味が腐っても回収できる）

案Bは痛み（「運用フラグを何度も手でタイトルに書いてる」等）が観測され、かつ専用操作より自由タグが明らかに安いと分かってからだけ再検討する。

## このカードでやらない

- 自由入力タグ付けUI・タグ別表示の実装
- タグの色・階層・オートコンプリート
- `Card.tags` フィールド削除（互換維持）
- `Card` への color フィールド追加
- ピン／未読の専用操作実装（必要なら別カード）

## 後続へ渡す最小要件（1段落）

自由入力タグはMVP外（案A）。表示切替はT018（糸＋考察）。意味はT028/T029。
`tags` 配列はスキーマに残すがUIは足さない。運用フラグが欲しくなったら自由タグ復活より専用操作を先に検討。
案B制約は上節。評価パケット T018-T020.md は失効のまま（タグ実装予算を投じない）。
