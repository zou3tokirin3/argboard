## 目的

探索モードの発見ログは発見順のフラットな一覧で、カードが増えると延々スクロールになる。
検索・未配置のみ（T040）・配置済のみ（T047）はあるが、「この資料はもう掘り終わった、閉じる」
ができない。

T050 の `foundVia` を親に使って、掘った構造そのままのツリーで見られるようにし、
**畳めるようにする**。フラットな一覧にはできないことがこれ。

出典: 2026-08-01 人間との設計相談（探索は見つけた構造を残す。横断的につなぐのは思考ボードの側）

## 背景（起票時メモ）

- depends on **T050**（`foundVia` がなければツリーは全部ルート直下＝ただのフラットリスト）
- 表示層のみ。`Card` に何も足さない。畳みは session のみでJSONに載せない
- Won't §12「カードの親子階層」への抵触は T050 側で判定済み。T051 は表示だけなので新たな抵触はない
- §1 の継承原則「発見順が基本」を壊さないため、**既存のフラット表示を置き換えずトグルで切り替える**。
  ボタンは未配置のみ／配置済のみと同じ並び
- 罠: 畳んだ親の下にキャプチャが吸い込まれると、ザクザクが壊れる
  → 直前に追加したカードの親は自動で開く
- 本体行が +200 を超える見込みなら、着手時に評価パケットへ回す（着手時判定）

## 受け入れ条件（起票時ドラフト・ready時に確定）

- [ ] 発見ログをフラット表示とツリー表示で切り替えられる（既定はフラット＝現状維持）
- [ ] ツリー表示では `foundVia` の親子で入れ子になり、親を持たないカードがルートに並ぶ
- [ ] 親カードを畳む／開くことができる
- [ ] 畳んだ状態でキャプチャしても、追加したカードが見えなくならない（親が自動で開く）
- [ ] 畳みの状態は session のみ（リロードで消える・JSONに載せない）
- [ ] 検索・未配置のみ・配置済のみと同時に使っても破綻しない（ready時に組み合わせ挙動を確定）
- [ ] ボードへのドラッグ配置・カード選択・削除がツリー表示でも動く
- [ ] flow しきい値の見込みを作業ログに書く。超過見込みならパケットへの人間GOがある
- [ ] 最新コミットで check / test / smoke が緑
- [ ] 人間が「掘り終わった資料を閉じて、発見ログが静かになる」と確認する

## このカードでやらない

- `foundVia` の記録そのもの（**T050**）
- 発見元の付け替え・ドラッグで親を変える操作（発見の構造は不変）
- 意味づけの糸をツリーに出すこと（ツリーは発見の構造だけ）
- ツリーの並べ替え・ソート順の選択UI（各階層は発見順のまま）
- 考察モード側・ボード側の表示変更
