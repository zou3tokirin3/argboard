## 目的

グラフが育つ過程（置いた・繋いだ・消した・要検討にした）を後から再生できるよう、
追記専用の操作イベント記録を始める。履歴は記録開始時点からしか存在しないため、
表示（T025）より先に記録だけを入れる。

出典: 2026-07-20 振り返り配信でグラフの育ちを追いたい需要を観測
優先度: 現行バックログ（T016–T022）を崩さない範囲の割り込み候補。早いほど履歴が残る

## 背景（起票時メモ）

- 現状で遡れるのは発見順(`foundAt`)と糸の作成順(`createdAt`)のみ。配置時刻・移動・削除・要検討の切替は失われる
- Projectへ任意フィールド `events?:` を追加する（schema v1互換・migration不要）。エクスポートJSONに自然に含まれ、履歴ごと別端末へ移送できる
- 変更操作は project.ts の純関数と state.ts の薄いラッパーに集中しており、フック点は少ない
- 起票時の設計判断:
  - 削除イベントには削除対象のスナップショットを同梱する（幽霊表示・復元・undoの土台。後付け不可）
  - 粒度は「操作の確定時」のみ。ドラッグ中の中間座標は記録しない（肥大防止・E2E安定）
  - プロジェクトを開いたイベントを1本入れる。振り返りの「第N回」チャプター境界が後から無料で立つ
- 副産物: 将来のundo/redoがほぼ無料になる。§16の「要検討を戻した履歴」「考察カードの状態履歴」も自然に解決する

## 受け入れ条件

- [x] Projectに任意のeventsが追加され、既存JSONはschema version 1のまま読める
- [x] カード追加・編集・削除、糸の作成・変更・削除、ボード配置、プロジェクトを開く、が追記される
- [x] 削除イベントに削除対象のスナップショットが含まれる
- [x] ドラッグ中の中間座標を記録しない
- [x] イベントはUIに出さない（記録のみ）。既存操作の体感速度を変えない
- [x] エクスポート→インポートでeventsが往復する
- [x] 行数警告基準（15ファイル / 3,000行）を意識し、超過見込みなら評価パケットへの人間GOが作業ログにある
- [x] 最新コミットで check / test / smoke が緑

## このカードでやらない

- 再生・履歴のUI（T025）
- undo/redo
- ログの圧縮・件数上限（肥大が観測されてから）
