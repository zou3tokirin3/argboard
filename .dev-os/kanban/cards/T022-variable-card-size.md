## 目的

全部同じサイズだと長いメモや短い手がかりの可読性が揃わない。
必要ならカードごとにサイズを変えられるようにする。

出典: T015 / O6
優先度: できたら（T019のプレビューで足りるか先に見てからでよい）

## 受け入れ条件

- [x] ボード上のカードについて、少なくとも2段階以上のサイズ（またはリサイズ）を選べる
- [x] サイズはプロジェクト保存に残り、export/importで復元される
- [x] 糸・ドラッグ移動・選択がサイズ変更後も破綻しない
- [x] 行数警告基準（15ファイル / 3,000行）を意識し、超過見込みなら評価パケットへの人間GOが作業ログにある
- [x] 最新コミットで check / test / smoke が緑
- [x] 人間が「サイズを変えて読みやすくできる」と確認する

## このカードでやらない

- 自由変形の高度なレイアウトエンジン
- メモ先頭プレビュー自体（T019）
- スクショの貼付・保存そのもの（T041。本カードは表示枠のサイズ側）

## 関連・引き継ぎ（T041 レビューより）

T041 でカードにスクショ1枚を載せるようにした。現状のボード／発見ログのサムネ寸法は
CSS と `NODE_WIDTH` / `NODE_HEIGHT` に直書き（例: ボード併記時 88×56、発見ログ 88×66）。
タグはノリ帯へ移し、ノリのドラッグ当たり（T014）は寸法固定のまま維持している。

本カードでサイズ可変にするときは、次をセットで見る:

- ノード幅・高さとノリ／糸ハンドル位置を**同じ寸法ソース**から決める（当たりを壊さない）
- 画像サムネ枠もそのサイズに追従させる（本文併記時の横並び含む）
- 発見ログ側サムネをボードと揃えるかは実装時に判断（最低でもボードは追従）

T041 では「貼れる」まで。大きさの柔軟化は本カード（T022）の責務。
