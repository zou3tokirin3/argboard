## 目的

現行ゲート（PLAN §4「実装ゲート」-3）の発火条件は「**残枠 < 見込み純増**」。
本体は警告基準 3,000行を超過しているため**残枠は負**であり、
以後すべてのカードが自動的に評価パケット対象になる。

**常時ONのゲートは情報を持たない。** 止めたいもの（スコープ膨張）と止めたくないもの（通常の実装）を
区別できていない。人間側には「毎回パケットで許可を求められる」という運用コストだけが残る。

本カードは基準値を上げ直すのではなく、**指標の種類を変える**。

## なぜ数字の再設定ではだめか

v1上限は M2 時点で 2,500 → 3,000 へ**一度だけ再設定した経緯**があり（PLAN §14 決定ログ）、
同時に再増額禁止を定めている。4,500 に上げても、同じ理由で数ヶ月後に同じ場所へ戻る。
現行指標は stock（累積）なので、**超過状態から回復する経路が構造的に存在しない**。

## やること（ready 確定・2026-07-26）

### 1. 発火条件を stock → flow へ

カードごとに下表を見込みで埋め、**1つでも超えたらパケット、全部下回れば素通り**。
実測は `deno task budget --since main`（T034）。しきい値は人間「次へ進んで」により planner 案を採択。

| 指標 | 測り方（budget 列） | しきい値 | 人間語 |
|---|---|---:|---|
| 純増（本体行） | 本体行数の Δ | +200 / カード | 一度に大きく足すこと |
| 操作の数 | 操作の数の Δ | +3 / カード | 新しい押せるものを増やしすぎ |
| 概念の数 | 概念の数の Δ | +2 / カード | 新しい用語・状態を増やしすぎ |
| 配布サイズ | 配布サイズの Δ | +8KB / カード | 利用者のダウンロードが増えすぎ |
| Won't 抵触 | §12 と目視 | Yes で無条件発火 | — |

### 2. 累積値は「基準」をやめて「計器」にする

stock（本体行・ファイル数・操作・gzip 等）は毎カードに記録するが、**それ自体では止めない**。
3,000行警告基準はゲート発火条件から外し、§14 に履歴として残す。

### 3. テスト枠を分離する

- `smoke` = **5本**（行数枠は撤廃）
- `unit` = 枠なし。ただし1カードで +150行超なら申告
- **flaky 台帳**: 作業ログに「flaky発生 n 回 / 修正に使ったループ数」を1行（§10-2）

### 4. 同期する文書

`PLAN.md` §4 / §10-2 / §11-3 / §14、`.dev-os/budget-review-packet.md` §1、
`.dev-os/kanban/_board.md` の done前チェック、必要なら roles。
