## 目的

現行ゲート（PLAN §4「実装ゲート」-3）の発火条件は「**残枠 < 見込み純増**」。
本体は 4,385行で警告基準 3,000行を +1,385 超過しているため**残枠は負**であり、
以後すべてのカードが自動的に評価パケット対象になる。

**常時ONのゲートは情報を持たない。** 止めたいもの（スコープ膨張）と止めたくないもの（通常の実装）を
区別できていない。人間側には「毎回パケットで許可を求められる」という運用コストだけが残る。

本カードは基準値を上げ直すのではなく、**指標の種類を変える**。

## なぜ数字の再設定ではだめか

v1上限は M2 時点で 2,500 → 3,000 へ**一度だけ再設定した経緯**があり（PLAN §14 決定ログ）、
同時に再増額禁止を定めている。4,500 に上げても、同じ理由で数ヶ月後に同じ場所へ戻る。
現行指標は stock（累積）なので、**超過状態から回復する経路が構造的に存在しない**
（T036 のリファクタを全部やっても −110行、4,385 → 約4,275 で 3,000 には届かない）。

## 現行指標の4つの欠陥（2026-07-25 実測に基づく）

1. **定義が一意でない** — 「本体行数」に 4,385 と 3,233 の2つの値がある（T031–T033 パケット §0 が自己申告）
2. **フォーマッタの関数になっている** — `board.tsx` 1,106行=21.9KB / `styles.css` 1,117行=18.3KB。
   同じ行数で中身が2割違う。§4-5 の「一行化での帳尻合わせ禁止」は、この指標がフォーマット依存だという自認
3. **stock を測って flow を測っていない** — 累積4,385行から、次の一手が暴走かどうかは何も分からない
4. **投資領域を予算が締め出している** — `styles.css` 1,117行 は本体予算の25%。§8 は
   「デザイン＝今回の新規投資領域」と宣言している。`createDemoProject` 74行（ロジックゼロの固定データ）も同じ枠。
   CSS・データ・ロジックを同じ物差しに載せているため、投資するほど機能が入らなくなる

## テスト枠の欠陥（別立て・§10-2 との関係）

PLAN §1 の敗因記述は「**E2E資産の無制限増殖と flaky 修正ループが本流を停止した**」。
痛みは *本流が止まること* であって、テストの行数ではない。

- **枠の切り方が逆**: テスト 1,273行 の内訳は `smoke.ts` **475** + unit **798**。
  前作を殺したのは smoke（E2E）なのに、安い unit と同じ800行枠に入れている。
  unit 798行は健全な資産で、これが枠を埋めて smoke を守れなくしている
- **効いている枠は行数ではなく本数**: §10-2「スモーク5本上限」は現に守られている（①〜⑤ で5本）。
  行数枠のほうは何も守っていない
- **決めたのに測っていない指標がある**: §10-2 は「flaky 修正は1ループまで、超えたら削除」と定めているが、
  flaky の発生回数も消費ループ数もどこにも記録がない。**前作の敗因の直接指標がこれ**
- **本流比率は測れる**: 前作は「全50コミット中、機能追加は約5個（10%）」。
  今回は全201コミット中 feat 20 / fix 34 / chore 127（うち dev-os 盤面 36）で **feat+fix = 27%**。
  前作の2.7倍。これは行数枠ではなく 5本上限と flaky 即削除が守った成果

## やること（改訂案・数値は ready時に人間が確定）

### 1. 発火条件を stock → flow へ

カードごとに下表を埋め、**1つでも超えたらパケット、全部下回れば素通り**。

| 指標 | 測り方 | しきい値（planner案） | 何を守るか |
|---|---|---:|---|
| 純増（本体行） | `deno task budget --since main` | +200 / カード | 一度に大きく足すこと |
| 操作の数 | ユニーク `data-testid` の増加 | +3 / カード | Won't侵入・UI膨張（現41） |
| 概念の数 | `types.ts` フィールド + イベント種別 + signals の増加 | +2 / カード | §5「3+1型のみ」の侵食（現77） |
| 配布サイズ | `dist/bundle.js` gzip の増加 | +8KB / カード | 利用者が実際に払うコスト（現27.3KB） |
| Won't 抵触 | §12 と目視照合 | Yes で無条件発火 | — |

代替指標はいずれも**フォーマッタ非依存**（バイト数・要素数・シンボル数）で、
コメントや空行を罰せず、CSS・データ・ロジックを公平に扱い、数え方が一意。

### 2. 累積値は「基準」をやめて「計器」にする

4,385行 / 13ファイル / 41操作 / 27.3KB を毎カードに記録するが、**それ自体では止めない**。
トレンドが見えれば足りる。3,000行という数字は削除するか、履歴として §14 に残す。

### 3. テスト枠を分離する

- `smoke` = **5本**（行数枠は撤廃。前作の敗因は本数と修正コストであって行数ではない）
- `unit` = 枠なし。ただし1カードで +150行超なら申告
- **flaky 台帳**: 「flaky発生 n 回 / 修正に使ったループ数」をカード作業ログに1行。
  §10-2 が既に上限を決めているのに未計測なので、ここが最も安く効く

### 4. 同期する文書

`PLAN.md` §4「予算（警告基準）」「実装ゲート」/ §10-2 / §11-3 / §14 決定ログ、
`.dev-os/budget-review-packet.md` §1 の様式、`.dev-os/kanban/_board.md` の done前チェック。
