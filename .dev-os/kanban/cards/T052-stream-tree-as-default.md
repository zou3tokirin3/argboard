## 目的

T051 でフラット／ツリーの切り替えを入れたが、探索で `foundVia` を使う以上、
**畳み付きツリーが実質の主画面**になりうる。毎回「ツリー」を押す摩擦が残るなら
既定表示またはトグル廃止を検討する。

本カードは実装より **dogfood 後の判断** を先に固定する。決まったら小さな実装カードに
切るか、本カード内で実装まで完結させる。

出典: 2026-08-03 人間相談（切り替え必要？標準にならない？）

## 背景（起票時メモ）

- depends on **T051** の人間確認（ツリーで「掘り終わった資料を閉じる」が成立していること）
- T051 起票時は §1「発見順が基本」のためフラット併存を選択した
- フラットも `sortCardsByFoundViaTree` + インデントで構造は見える。**ツリーの差分は主に畳み**
- 候補:
  - **A**: 探索モードの既定をツリー ON（トグルは残す・session または ui に記憶はしない）
  - **B**: トグル廃止・常にツリー + 畳み（フラット削除）
  - **C**: 現状維持（フラット既定・トグル併存）
- 判断材料: T051 dogfood でフラットに戻る場面があるか／`foundVia` なしプロジェクトでの見え方

## 受け入れ条件（起票時ドラフト・ready時に確定）

- [ ] T051 が done（または rework 理由がツリー自体でない）
- [ ] 人間が探索セッションでフラット／ツリーを両方触り、戻る理由の有無を作業ログに残す
- [ ] A / B / C のいずれかに決定し、理由を作業ログに1行で書く
- [ ] 決定が A または B なら実装し、探索を開いたときツリーが標準になっている
- [ ] 決定が B なら「ツリー」トグルが消え、畳み・入れ子・キャプチャ時自動展開は維持
- [ ] 決定が C なら実装なしで done（本カードは判断記録のみ）
- [ ] 実装した場合: check / test / smoke が緑
- [ ] 人間が探索の初見で「わざわざ切り替えなくてよい」と確認する
