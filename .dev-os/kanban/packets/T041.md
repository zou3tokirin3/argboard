### 6. リスクと確認方法

- 壊れうる既存操作:
  - JSON エクスポート／インポート（拡張子・accept・ドラッグ&ドロップ）
  - カード削除・プロジェクト切替・全置換保存
  - `db.ts` の Store 差し替え契約（§6）。Blob store を同ファイルに足すと乗り換えコストが上がる
  - 既存プロジェクトの `image` に URL 文字列が入っていた場合の扱い（デモに無ければ無視でよいが、読み込み時のフォールバック方針が要る）
- GO後の人間確認（3ステップ以内）:
  1. カードを選びスクショをペースト → 1枚表示。もう1枚ペーストすると差し替わる（増えない）
  2. リロード後も画像が残る
  3. zip エクスポート→インポートで画像込み復元。別途 `.json` だけも従来どおり読める
- 見積もりが外れやすい点:
  - **自前 zip**（エクスポート／インポート往復と既存 `.json` 両立）が一番膨らみやすい
  - IndexedDB version 上げと GC（孤児 Blob）の漏れ
  - ボードサムネのレイアウトが `NODE_HEIGHT` / ノリ当たり（T014）へ波及すること
  - gzip が +8KB を超えた場合（自前 zip が大きいとき）
