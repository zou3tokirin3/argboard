# argboard 文言差し替え・多言語化 設計方針（確定・実装承認なし）

## 依頼（マネージャー経由・2026-11-07 14:06 JST 隆さん原文）
「argのやつ、各種ワード気に入らないとか、外国語対応で簡単に差し替え可能にできる？」→「相談して決めて、人間いじらずAIがやる」
- 人が辞書を直接編集・設定画面は不要。AIへの自然文依頼で変更。T098に混ぜない。

## 確定方針
1. 構成: 依存追加なし。`src/i18n/ja.ts`（既定・正本, `as const`）＋`en.ts`（`satisfies Messages`で欠落キーは tsc でビルド失敗）＋`t(key, params)`。キーは意味ベース（例 `inspector.title.label`）、文は丸ごと（語の継ぎ接ぎ禁止）。差し込みは型付き `{name}`。日付・数は `Intl.DateTimeFormat`/`Intl.PluralRules`。
2. 最初の範囲: 画面ラベル・ボタン・placeholder・aria-label/title・エラー/トースト・prompt/confirm。抽出PRは日本語のまま見た目変化ゼロ（スクショ 1280/390 差分なしが受入）。
3. 境界（訳さない）: 保存データ(カード本文・タイトル・タグ・糸ラベル等のユーザー入力)、ID/enum値、IndexedDB形式、event/room op プロトコル、エクスポート形式。画面用の生成履歴文は棚卸すが既存保存済み履歴は書き換えない。表示時だけ文言へ変換。差し込みはテキストで扱い、生HTML化しない。
4. 既定・欠落: 既定 ja。対応言語は型でキー完全性を強制→実行時の欠落は原則起きないが保険で ja にフォールバック＋開発時 console.warn。
5. 言語選択: 英語は抽出後の別段階。URL `?lang=ja/en` のみで選択し、未指定・未対応値は日本語。人手編集UI・永続設定・ブラウザ自動言語判定・実行時AI翻訳は作らない。
6. AI向け手順: `docs/i18n.md`（用語集: カード/糸/ボード等の ja↔en 対訳と禁止訳、ルール、チェックリスト）＋AGENTS.md から参照。呼び名変更は「用語集→ja.ts→en.ts→テスト」の順。
7. 検証: tsc（キー完全性）、node:test で「全ロケール同一キー・差し込み変数一致」、ソース内の直書き日本語UI文字列を検出するlint/テスト（許可リスト: ja.ts, テストfixture, コメント）、既存smoke回帰、英語PRは1280/390スクショ。
8. 計画（T098完了後・最新mainから小PR）: ①基盤・用語集・AI手順・検査と画面単位の日本語抽出（表示不変）②英語ロケールと言語選択。現在は計画のみ、新規実装・PR・マージは未承認。
