日本語の正本は `src/i18n/ja.ts` の `ja as const`。`Messages` は同じキーを持つ文字列型。
現時点は日本語のみ。英語辞書・URL `?lang=`・自動判定・設定保存は実装しない。

## AIが変更するとき

1. 自然文の依頼から対象と意味を確かめ、用語集を更新する。
2. `ja.ts` を更新する。キーは `imageOverlay.dialog.label` のように意味で固定し、呼び名変更で改名しない。
3. 英語導入後は `en.ts`（`satisfies Messages`）も更新し、node:test の辞書一覧に登録する。今回は追加しない。
4. 型・キー・差し込み検査と画面の検証を実行する。

- 文は丸ごと持ち、単語の連結で文を組み立てない。差し込みは `{title}` の形式。
- `t("imageOverlay.dialog.label", { title })` を使う。キー・必須変数は型検査される。
- 戻り値をJSXテキストや属性に渡す。`innerHTML` / `dangerouslySetInnerHTML` に渡さない。
- 差し込み値内の `$&`・`{title}`・HTML風の文字は再解釈しない。
- 日付・数の表示整形が必要な場合は `Intl` を使う。今回の抽出に整形変更を混ぜない。
- 実行時に辞書の文が欠けた場合は日本語へ戻す。`createTranslator(catalog, development)` は開発時だけ警告できる境界。現在の `t` は正本jaを直接使う。
- ユーザー入力（タイトル・本文・タグ・糸ラベル）、ID・enum、IndexedDB、event/room op、export形式を翻訳・変更しない。
- 生成履歴文は後続で棚卸しする。保存済み履歴を書き換えない。

## 今回の範囲と分割計画

全UI抽出は約400コード行を超えるため、画面ごとに分割する。

- slice1（#12、マージ済み）: 基盤と `ui/image-overlay.tsx` の画像拡大画面。拡大ボタンのaria/title、画像alt、ダイアログaria、編集ヒント、閉じるボタンの6文言。placeholder・エラー・toast・prompt・confirmはない。
- slice2（マージ済み）: `ui/card-image-field.tsx` の画像添付欄のみ。compact / inline のラベル・ヒント・選択/差し替え/削除ボタン・画像alt・添付失敗時のフォールバックエラーを原文のまま抽出（11キー追加）。拡大のaria/titleはslice1の2キーを再利用し、画像拡大画面自体は変更しない。placeholder・toast・prompt・confirmはない。
- slice2のエラー境界: 添付欄内の非Errorフォールバックだけが対象。`error.message` は従来どおり表示し、上流の `state.ts`（ファイル形式検証）、`image-compress.ts`（圧縮失敗）、ブラウザ由来の例外は後続で棚卸しする。画像入力エラー全体が抽出済みという意味ではない。
- `pasteExploreImage` → `stageExploreImage` → `exploreImageDraft` と `capture.tsx` の画像準備/参照UIを調査。captureは約1000行で他の入力・ヒントも混在するため、slice2へ追加せず後続の独立スライスにする。

- slice3（今回）: `capture.tsx` から画像選択・貼り付けの `CaptureImageSlot` と既存の作中時間補助関数を `ui/capture-image-slot.tsx` に移動。4キー追加、添付失敗の非Errorフォールバックは既存の `cardImage.attach.error` を再利用（2箇所）。title・aria-label・エラーのみで、表示テキストや操作は維持。placeholder・toast・prompt・confirmはない。新しい用語はない。
- slice3の境界: `capture.tsx` 本体（ドロップのフォールバックを含む）、画像準備・参照画面、`state.ts` / `image-compress.ts` の上流エラーは未抽出。元ファイル全体に検査免除を作らず、独立した画像入力面だけを厳密検査する。

直書き検出は既存依存esbuildでTSXを解析しコメントを除去してから日本語を検出する。
検査の厳密な対象リストは `tests/unit/i18n.test.ts`。現在は上記2ファイルとslice3の `ui/capture-image-slot.tsx` のみで、全UIの抽出完了を意味しない。
正本 `ja.ts`・テスト/fixture・コメントは許可する。抽出対象を増やすたび検査リストも増やし、対象内の除外を作らない。

後続PR（それぞれ日本語表示を維持、約400行以内）:

1. Captureの画像入力面に続き、画像準備/参照を独立した面に分割し、日本語抽出と厳密検査対象追加。`state.ts` の画像形式検証と `image-compress.ts` の圧縮失敗も境界をそろえて抽出する。約400行を超える場合はさらに分ける。
